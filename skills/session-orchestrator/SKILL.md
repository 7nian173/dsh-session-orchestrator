# 会话编排插件 · 使用说明

这份文档回答一件事：**人类说这些话时，我该怎么做。**

不涉及插件实现、不涉及内部机制。你要做的就是照着做。

---

## 1 本插件能做的四件事

| 人类的意思 | 你调什么 |
|---|---|
| 把一个目录登记成 DSH 工作区，并开一个会话 | `session_init_workspace` |
| 给自己或别人起个可寻址的名字 | `session_register_name` / `/register-me` / `/register-peer` |
| 给某个会话寄一封信 | `mail_send` |
| 把界面切到某个会话 | `session_jump` |

**这四件之外，不要往本插件上靠。**

---

## 2 「建工作区」

### 只有一种做法

> 在指定目录登记 DSH 工作区，并开一个会话。

### 两条入口，效果一样

| 入口 | 样子 |
|---|---|
| 人类说 | 「帮我建立个新的工作区」「帮我建立个 dsh 工作区」（必须出现「工作区」三字） |
| 人类敲 | `/new-workspace 项目名 [目录]` |

命中的条件很窄。**「建个项目」「整理目录」「建 git 仓库」不算**，那是普通对话，别扯本插件。

### 你只问两件事

1. **目录放哪**（没给就用 `ask_user_question` 让他选；不要自己往 C 盘或系统目录建）
2. **项目叫什么**

一次问完，两个问题。

### 这几句不要问

| ❌ 不要问 | 说明 |
|---|---|
| 「你要建哪一种工作区？」 | 本插件只有一种 |
| 「这个工作区拿来做什么？」 | 跟登记动作无关 |
| 「要 Node 还是 Python 骨架？」 | 不归本插件管 |
| 「要不要生成 README / AGENTS.md / .gitignore？」 | 不归本插件管 |

### 什么时候不用本插件

| 人类说 | 你该做 |
|---|---|
| 「把这个目录整理成规范结构」 | 普通文件操作 |
| 「给项目补个 README」 | 普通文件操作 |
| 「生成一个 ×× 技术栈的骨架」 | 普通文件操作 |
| 「登记成 DSH 工作区并开会话」 | ✅ 用本插件 |

拿不准就问**一句**：「是要登记成 DSH 工作区并开会话，还是整理目录结构？」

一个问题就够，**不要列三四个方案让人选**。

---

## 3 「注册好友」

### 先分清注册谁

| 人类说 | 目标 | 怎么做 |
|---|---|---|
| 「把你自己注册成 xx」「你叫 xx」 | 当前会话 | `session_register_name`，或让他敲 `/register-me xx` |
| 「把那个会话注册成 xx」「他叫 xx」 | 别的会话 | 先确认目标，再 `/register-peer` 或 `session_register_name` |

### 名字照他写的来

人类写什么就是什么。插件会自动清理（空格换成连字符、删掉标点、太长截断），并告诉他最后叫什么。
**不要说「名字不合法，请按格式写」**。

### 目标对不上就给候选

不要回「格式错误」。按情况办：

| 情况 | 做法 |
|---|---|
| 给了会话 id | 直接注册 |
| 只给工作区名，**唯一命中** | 直接注册 |
| 只给工作区名，**多个命中** | 用 `ask_user_question` 列成选项让他挑（带「取消」项） |
| 信息对不上 | 列出现有会话让他挑，别让他记格式 |

---

## 4 「给谁发信」

1. 先确认收件人：`session_list_names` 或 `mail_friends` 找名字；不确定就列候选问
2. 收件人还没注册 → 先注册
3. `mail_send` 发信；急事加 `urgent: true`；过时的用 `S-EXPIRE` 撤销
4. 回报：信 id、当前状态，并**说明对方默认不会被打断**（他自己开工时会取）

### 回信不等于结案

收到信要结案，必须单独 `mail_ack` 原信。回一封新信不算。

---

## 5 「跳到某个会话」

`session_jump`，排队一次跳转。目标不确定就先给候选让他挑。

---

## 6 三条通用规矩

### 宽进严出

| 人类给的信息 | 你怎么反应 |
|---|---|
| 齐全 | 直接做 |
| 缺一点 | **自己补**，只问真正缺的（最多两个问题） |
| 写错了 | **自动修正，并告诉他改成了什么** |
| 对不上 | **给候选让他挑** |

**永远不要**说：「参数不对」「格式错误」「请按以下格式输入」。

### 注册完教他怎么继续

回执里已经带好了这段话，直接沿用：

```
┌ 接下来你可以直接对我说：
│ 「把<要说的内容>送给<注册名>」
│ 或者你用自己的说法告诉我，说一次我就记住。
```

听到新说法，用 `prefs_set { phrasing, means }` 记下来；下次开工 `prefs_get` 看一眼。

### 归档会话在这里不存在

DSH 归档一个会话后，它的名字立刻失效（`FRIEND_ARCHIVED`），也不再出现在候选里。
**这只是本插件自己的规矩**。别拿它解释 DSH 原生列表的行为。

---

## 6.5 哪些事要先问人

下面这些**不能自己决定**，必须先拿到人的明确同意：

| 动作 | 为什么 |
|---|---|
| 递归删除工作区目录 | 删了就没了；必须先把警告原文转述给他，等他确认 |
| 装 skill / 改设置 | 属于他的环境，不是你的地盘 |
| 替他决定哪个会话该注册 | 名字是全局的，撞了会影响别人的通信 |

**你随时可以做的**：发信、注册（他明确要求时）、跳转、查列表。
**他自己说过的就算同意**——他说「帮我建个工作区」，那就是同意了，不用再问一遍。

## 7 命令的两个注意事项

**光敲命令名不会执行。** `/register-me`、`/register-peer`、`/new-workspace` 都要求跟参数，只敲命令名回车什么都不发生。要么让他补参数，要么你直接调工具。

**出错一定会显示。** 看到 `/命令名 执行出错：<原因>` 就照原因处理。
如果执行后**一点反应都没有**，那不是插件内部失败，而是命令没被执行——补参数重发，或改用工具。

## 8 关于「要不要装更详细的说明」

还有一份更详细的说明书：`docs/AGENT-GUIDE.md`（插件自带，随插件一起发布）。

**如果需要更完整的功能说明，可以把它作为 skill 装进项目。但这是人类的决定：**

> **不要自行安装。先问他：「要不要把会话编排插件的详细说明装成 skill？装了之后我处理这类请求会更准。」**
>
> 他同意再装；不同意就用手头这份。

判断标准只有一个：**这份说明是否真的不够用**。够用就别提。
