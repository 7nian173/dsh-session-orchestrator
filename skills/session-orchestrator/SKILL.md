# 会话编排插件 · 自然语言操作手册

人类不会说命令名。他只会说「帮我建个工作区」「把这事告诉决策」。
这份手册的作用：**把他的口语翻成本插件的正确动作，并挡住过度解读**。

工具的完整参数见 `docs/AGENT-GUIDE.md`（插件自带）。这里只管**怎么判断意图**。

---

## 0 一句话认插件

本插件只做四件事：

| 人类的意思 | 动作 |
|---|---|
| 把一个目录登记成 DSH 工作区，并开会话 | `session_init_workspace` |
| 给自己或别人起个可寻址的名字 | `session_register_name` / `/register-me` / `/register-peer` |
| 给某个会话寄信 | `mail_send` |
| 把界面切到某个会话 | `session_jump` |

**这四件之外，一律不是本插件的事。**

---

## 1 「建工作区」——最容易搞错的一条

### 本插件的「建工作区」只有一个意思

> 在指定目录登记一个 DSH workspace，并立刻开一个会话。

工具：`session_init_workspace(project, workspace, preset, title)`

### 只问两件事

1. **目录放哪**（没给就用 `ask_user_question` 让人选，**不要自己往 C 盘或系统目录建**）
2. **项目叫什么**

一次问完，两个问题。

### 绝对不要问这些

| ❌ 不要问 | 为什么 |
|---|---|
| 「你要建哪一种工作区？」 | 本插件只有一种 |
| 「这个工作区拿来做什么？」 | 跟登记动作无关 |
| 「要 Node 还是 Python 骨架？」 | 不是本插件的职责 |
| 「要不要生成 README / AGENTS.md / .gitignore？」 | 同上 |

### 什么时候**不该**用本插件

| 人类说 | 该怎么做 |
|---|---|
| 「把这个目录整理成规范结构」 | 普通文件操作：补 `AGENTS.md`、目录结构、忽略规则 |
| 「给项目补个 README」 | 普通文件操作 |
| 「生成一个 ×× 技术栈的骨架」 | 普通文件操作 |
| 「登记成 DSH 工作区并开会话」 | ✅ `session_init_workspace` |

**拿不准就问一句**：「是要登记成 DSH 工作区并开会话，还是整理目录结构？」
一个问题，**不要列三四个方案让人选**。

### 门控

设置里「允许 Agent 通过本插件新建会话」默认**关**。

- 人类**亲口说**了建工作区 → 插件会认出来，放行。
- 你自己起意 → 返回 `AGENT_CREATE_DISABLED`。这时**不要绕路**（别手工建目录、别上脚本），
  告诉人类去 **设置 → 会话编排 → 安全** 开启，或改用 DSH 原生的新建会话。

## 2 「注册好友」

先分清注册**谁**：

| 说法 | 目标 | 走法 |
|---|---|---|
| 「把你自己注册成 xx」「你叫 xx 吧」 | 当前会话 | `session_register_name` 或让人类敲 `/register-me xx` |
| 「把那个会话注册成 xx」「他叫 xx」 | 别的会话 | 先确认目标，再 `/register-peer` 或 `session_register_name` |

### 名字不要挑刺

人类写什么就是什么，**插件会自动清洗**：空格折成连字符、标点删掉、超长截断。
回执会告诉他最终叫什么。**不要回「名字不合法，请按格式写」**。

### 目标对不上怎么办

不要报「格式错误」。给候选：

1. 只给会话 id → 直接注册
2. 只给工作区名 → 唯一命中就注册，多个就**用 `ask_user_question` 列成选项让他挑**（带「取消」项）
3. 给的信息对不上 → 列出现有会话让他挑，别让他记格式

---

## 3 「给谁发信」

1. **确认收件人**：`session_list_names` 或 `mail_friends` 找名字；不确定就列候选问
2. 收件人没注册 → 先注册
3. `mail_send`，急事加 `urgent: true`，过时的用 `S-EXPIRE` 撤销
4. 回报：信 id、当前状态、**说明对方默认不会被打断**（会自己在开工时取）

### 别用「回信」代替「回执」

收到信要结案，必须单独 `mail_ack` 原信。回一封新信不算。

---

## 4 「跳到某个会话」

`session_jump`，排队一次跳转。目标不确定就先给候选。

---

## 5 通用的交互铁律

### 宽进严出

| 人类给的 | 你的反应 |
|---|---|
| 完整的 | 直接做 |
| 缺一点 | **自己补**，只问真正缺的（最多两个问题） |
| 写错了 | **自动修正并告诉他改成了什么** |
| 完全对不上 | **给候选让他挑**，不要说「格式错误」 |

**永远不要**：回「参数不对」「格式错误」「请按以下格式输入」。

### 注册完成后教他怎么继续

回执里已经带了这段，直接沿用：

```
┌ 接下来你可以直接对我说：
│ 「把<要说的内容>送给<注册名>」
│ 或者你用自己的说法告诉我，说一次我就记住。
```

听到新说法就 `prefs_set { phrasing, means }` 记下来；下次开工 `prefs_get` 看一眼。

### 归档会话在这里不存在

DSH 归档一个会话后，它的好友名立刻失效（`FRIEND_ARCHIVED`），也不再出现在候选里。
**这只是本插件的卫生规则**，别拿这个解释 DSH 原生列表的行为。

---

## 6 命令光敲名字不会执行

`/register-me`、`/register-peer` 都声明了输入提示，**只敲命令名回车什么都不发生**（DSH 停在等参数）。
所以要么让他补参数，要么你直接调工具，别在命令上空转。

---

## 7 出错了要说出来

所有斜杠命令都包了异常回显，看到 `/命令名 执行出错：<原因>` 就照原因处理。
**如果你执行命令后什么反应都没有**，那不是插件内部失败，而是宿主没执行——补个参数重发，或改用工具。
